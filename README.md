# Athena NSS 主线记录

Athena AX6600 网络优化研究。唯一主线：**自动识别游戏流 → NSS RT / bulk leaf → 真人 CS2 + Steam 高负载闭环**。

这是私有研究仓库，用来跨对话保存代码、可核对证据和下一步。现场凭据、完整连接元组、路由器配置备份和模块二进制仍保存在原本的本地工作区。

## 从这里继续

1. 阅读 [当前状态](docs/STATE.md) 和 [下一步](docs/PLAN.md)。
2. 阅读 [操作约束](AGENTS.md)，核验现网，再考虑任何写入。
3. 通过 [实验记录](docs/EXPERIMENT_LOG.md) 与 [证据索引](docs/ARTIFACT_INDEX.md) 区分实测、模拟和假设。
4. 每轮更新状态、证据和代码清单，提交一个明确说明结果的 commit。

## 当前结论

- 当前常驻分类器为 NSS37：保留 NSS35 地址恢复和 NSS33 精简发布，只优化连接文本属性搜索，所有身份/分类/新鲜度边界保持原样。
- NSS32 已通过受控低负载 TCP + UDP 的软件 → NSS → 软件验证；该证据不代表真人高负载体验通过。
- NSS36 完成 299 项分层检查；真实 WAN1 CS2 + Steam 短测在 ECM 开放前因时间余量不足退出，回滚核验通过。这是历史失败，不因本次优化抹去。
- **当前 ECM / NSS 加速关闭；真人高负载闭环尚未通过。**
- NSS37 新执行 9,087 项解析检查与 26 项生命周期模拟，目标机 16 对同输入测量的解析 CPU 耗时下降约 40%–43%。这是解析函数收益，不是整机 CPU 或 NSS 收益。
- NSS37 实际完成一次 180 秒独立到期回滚，重新 checkpoint、安装并提交保留。最新控制器已绑定新配置，目标预检与 10 项同 WAN 选择约束通过。
- 初始准入要求采集年龄小于 1 秒。下一步验证代表性负载下的发布时间与入口余量，再集中真人复测；无需持续挂游戏。
- 另有 407.82 Mbps 的软件诊断窗口，未包含成功的 NSS 阶段，不能当作 CPU 或游戏收益证明。完整高负载稳定性仍未通过。

最新现场状态、时间与证据编号见 [STATE.md](docs/STATE.md)。阅读源码副本不会获得操作现网的权限；部署仍须本地私有适配器、最新检查点和独立超时恢复。

## 目录

| 路径 | 用途 |
| --- | --- |
| `docs/` | 状态、计划、决策、逐轮记录与接续说明 |
| `evidence/` | 脱敏的结构化观测与结论边界 |
| `code/` | 精确保存的部署源文件与实验代码，原相对路径保留 |
| `tools/` | 从私有工作区按白名单同步、检查仓库内容 |
| `source-manifest.json` | 来源路径、内容哈希与部署匹配关系 |

代码镜像不是通用安装包，未附带运行所需的私有状态文件。不要直接运行现场控制器，也不要从旧的 `deployment-latest.json` 推断当前部署。详见 [本地接续](docs/LOCAL_SETUP.md)。
