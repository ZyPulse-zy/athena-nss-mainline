# 保守游戏优先 WAN6 已启用

六账号双向 NSS 保持运行。游戏入口只对 **新的 IPv4 LAN UDP 连接第一包** 生效，包长 28–256 字节、源端口不低于 1024，且目的地址必须是 Steam 官方 CS2 SDR 配置中公布的具体中继。当前 214 地址分两组：69 地址允许 27015–27044，145 地址允许 27015–27050（与原保守端口范围取交集）。不使用整个云服务商网段或全 UDP 分流。完整非 WAN mark 位保留；已有 WAN/NAT 归属的连接不迁移。

未匹配的游戏、未公布具体地址的第三方/合作中继、其他服务器与普通流量，继续原 WAN1–5 的 300 桶和既有 NSS RT 分类。命中首包路由本身不强制授予 RT 或硬件准入，原精确 CT/NAT、32 槽、六秒租约、双向 QoS 和回执合同保持。

## 已确认的排除与误识别边界

排除 QUIC/UDP443、DNS、DHCP、时间/发现/控制流量、已知 VPN 端口、代理 mark 和已知端点、Fake-IP、Tailscale 接口/CGNAT、私有/链路本地/文档/多播/保留地址。用户确认中山大学；官方 DNS 说明和门户/教务/认证/VPN 解析地址已核对，网关为私有地址，公开关键地址由保守的 `202.116.0.0/16` 排除覆盖。这个较宽排除是策略选择，不声称整个 /16 都属于中大，或已枚举所有未来校内公共业务。未列入游戏地址表的目标不会被选到 WAN6，因此未枚举的普通校园目标同样走原五路。

端口/小包/中继地址仍不能证明应用身份：同一官方中继上的探测、语音或自定义同服务隧道仍可能命中。未知服务器、大首包或范围外端口则会漏识别并留在五路 NSS 兜底。刻意构造的同端点“非游戏”样本不能变成现实误识别率；本轮没有测得真实误识别率。

## 资格、维护和回退

现有健康循环每次重新检查六账号认证地址、健康、同 boot 的 NSS 状态、来源/十二预算新鲜度、双向队列标签及实际内核 gate。资格只续 15 秒，WAN6 不健康、状态失真或续期停止时，新连接回到原五路；已经建立的 WAN6 NAT 会话保留归属。

在原健康循环中每天检查官方地址更新，没有新增常驻服务或调度。失败最多每小时重试，保留已验证缓存；缓存超过七天便停止选择新的 WAN6 游戏连接。更新采用限时、限体积 HTTPS 和原 hostname 验证，严格校验具体 IPv4/公布端口并限制为现有保守范围。现网默认 DNS 的 Fake-IP 会让路由器自身直接抓取失败，本维护请求仅通过已核对的中大 DNS 解析该 API 的真实地址，再使用 TLS `--resolve`；全局 DNS 与代理未改。目标真实下载已验证。

私有文件、互斥锁和当前/待提交缓存哈希约束注册更新；重启、PBR 表重建或已注册更新中断后，只重建游戏专属对象，以空资格开始。关闭/回退先删专属 hook/链/set 和标记，再按候选/已注册更新哈希恢复代码文件及健康进程，不停止 source/native，不动原五 buckets/sticky、认证、路由表或 NAT。

两次早期观察因检查耗时超过控制端续期时限而自动撤回，游戏专属回退实际成功，NSS/source 未停止；失败/撤回记录保留。最终检查通过后已提交启用，独立部署 guardian 正常退出。需要回到旧六 WAN 平台检查点时，先用本轮游戏检查点恢复旧游戏/健康文件，再进行之前的完整平台回退，避免覆盖未登记的新文件。

## 验证和未验证

五/六账号各 14 Lua + 2 C 回归、54 Lua/12 shell 语法通过，游戏策略 85 项检查及执行真实 runtime 的虚拟文件/命令模型累计 95 项。模型覆盖旧连接不迁移、非中继同端口排除、每地址端口上限、代理/校内/VPN、资格失效、实际 gate、重启重建、官方更新失败、七天过期、更新哈希与独占回退。目标 Lua 虚拟 I/O 模型、真实 nft check-only、目标锁能力和真实 DNS/TLS 官方抓取通过。

启用后保护审计通过：六账号在线；NSS/source/认证/autorate/代理/Tailscale等核验 PID、网络/防火墙/无线/source 指针/MAC map 保持；原 300 个桶只指向 WAN1–5；WAN6 双向 RT 标签 `7e66/7a66` 保持，未重启 NSS 或整台路由器。

最终 63.42 秒、21 样本全部 native-running/sourceFresh、游戏资格有效，pending/未确认为 0。期间新增来源暂停/恢复为 0；累计来源暂停/恢复为 1/1，不能声称整个工作窗口毫无来源间断。**本观察没有新的游戏候选命中，因此本轮真实游戏 UDP 的 CREATE、字节进展和游戏延迟效果未验证**；没有把之前 WAN6 TCP 的双向 NSS 成功冒充本轮游戏成功。实际冷启动和长期稳定性未测，没有主动启动游戏、造拥塞或故障注入。
