# 预算慢查询审计与单次只读 netlink 采样

2026-10-16，用户继续授权查因并修复，保持安全检查、不重启整机。维护起点 `f8a3dc4`；此前拓扑整轮限时和心跳故障快照保持。PR #1 继续 draft。

## 能确认的原因

原故障预算第一条 `cake-up-1` 查询耗时 4.00 秒，退出码 143（SIGTERM），失败种类为 `qdisc-command-failed`；不是十二条命令累计四秒，也不是预算 JSON 解析耗时。已有记录没有当时进程等待栈，不能追溯到底由哪个进程占锁或哪次调度导致延迟。

本机配对 6.18.44 内核 `tc_dump_qdisc` 持有 RTNL 并遍历全部 netdev/qdisc，没有使用请求中的设备条件。匹配的 [iproute2 v6.18.0 `print_qdisc`](https://github.com/iproute2/iproute2/blob/v6.18.0/tc/tc_qdisc.c) 在用户态按 ifindex 筛选。原采样每秒调用十二次 `tc ... qdisc show dev ...`，因此重复十二次全局 dump，放大网络配置锁竞争、进程启动和遍历开销。这是已确认的低效路径，不能将它冒充历史四秒等待的唯一触发原因。

不能直接改成一次 `tc -j qdisc show`：现场标准 tc 对 NSS 类型写出 `"options":{[Unknown qdisc, optlen=12] }`，在 nsshtb 对象处产生无效 JSON；`-j` 和 `-j -d` 均复现。没有截取、修补或从坏 JSON 中捞取部分对象作为预算。

## 修复

新增独立用户态 `cake-budget-read`，只向内核发送一次 `RTM_GETQDISC` dump，无 NEW/DEL、qdisc 配置、NSS 控制或流量注入。使用原接口的 sysfs ifindex，严格检查内核发送方、序号、消息/属性长度、截断/中断/错误、dump 完成，以及十/十二个指定根的完整性；仅匹配 root CAKE，重复、缺失、无效/不限速/越界速率全部拒绝。直接读取 CAKE `BASE_RATE64` 字节速率，不经人类可读单位四舍五入；非目标 NSS 属性不解释。完成后再次核对接口索引，未确认全部根前不输出可用预算。

一次用户态采样预算仍为 0.75 秒，外层原 `timeout -k 1 1`、writer 六秒预算/CT 时效、八秒 reader 心跳、32 槽、源不完整拒绝、固件精确回执和有限重试均保持。内核不可中断等待或整机调度停顿仍可能推迟用户态返回；程序返回后再次检查总耗时，不能把晚到数据标为新鲜。没有延长预算掩盖超时。

预算采样器增加查询阶段，并跨后续成功采样保留最近一份失败摘要、原始时间与诊断；不刷新失败时间或 CT heartbeat。已有失败退出快照会包含此状态。launch 将匹配 ARM64/musl 程序复制到私有 RAM 目录并设 0700；原构建入口及独立 userspace 构建脚本均包含此依赖。没有内核、无线驱动或固件替换。

boot、保护文件哈希、六账号接口/地址、原 PBR/NAT/代理规则、无关服务身份及十二软件 CAKE 根/固定选项保持；原 autorate 的动态 bandwidth 仍由其自己管理。仅 NSS 和它拥有的 core guard 按正常生命周期切换；不能称为整个部署无加速间断，未迁移 NAT。原无线、认证、代理/Tailscale 和磁盘模块保持。

最后状态与源码/目标哈希、检查统计见[匿名证据](../evidence/dorm-v2-budget-netlink.json)。没有现场故障或拥塞注入、真实 4 秒等待复现、独立回退到期触发、逐流 firmware 字节或端到端游戏/长期验收。历史具体持锁者/调度原因仍未证明，此修复不能保证所有底层停顿消失。

健康循环、原 autorate 和 NSS class 更新等其他调用方仍可能共享 RTNL；本轮只减少独立预算入口的重复 dump，没有替换这些策略或重启健康服务。运行中的健康服务仍持有其启动时加载的恢复检查函数，正常 NSS 活跃时不会进入该额外恢复路径；下一次服务自然加载会使用新 collector 和持久 helper。该旧恢复函数保留原有安全检查。
