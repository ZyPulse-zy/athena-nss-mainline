# 拓扑整轮限时与心跳故障快照

2026-10-16 用户授权修复并部署，不重启路由器整机。维护起点为远端 `3e7f894`；八份关键安装源码与该版本逐字节一致，行为代码仍包含此前 `8621136` 的独立预算修复。PR #1 保持 draft，不合并。

## 现场原因与边界

第一轮自动重试的直接原因是 `reader-heartbeat-missing-or-stale`。最后进度为 `iw-phy18-ap0`；最后完整预算十二读全部成功、耗时 0.21 秒。21:15:45 确认回退，21:15:54 新会话开始。进度记录只能定位最后阶段，不能证明一定是该驱动调用本身卡死。

修复准备期间又发生第二轮自然重试，23:00:34 左右确认回退。这次是 writer 的软件预算过期异常：最后不完整预算耗时 4 秒，只执行了一条队列查询，预算采样状态仍为 collecting；reader 同时在 hostapd 查询阶段。独立预算子进程并未被撤销或重新耦合到拓扑。现有证据不能区分内核等待、系统调度停顿等原因，不能宣称此次拓扑修复已经解决所有预算或系统阻塞。两个原事件的记录留在私有检查点，不公开 CT、客户端或认证数据。

## 改动

- `collector.topology` 每轮使用一次绝对 3.5 秒截止时间。每次启动原有查询前，必须留足原 `timeout` 的一秒 TERM、一秒 KILL 以及 0.1 秒余量；不够就跳过后续查询，记录 `topology-time-budget`、跳过命令、开始/结束/截止时间。查询返回后和整轮结束时再次检查截止时间。
- 查询或解析晚于期限时发布 `complete=false`；没有旧拓扑缓存、没有重新标注旧数据时间。现有 core/writer 会按源不完整停止准入或续租，保持软件退路。预算采样仍是独立的每秒只读子进程。
- 心跳超时在回退前保存 reader 进度、预算采样器状态、软件预算发布元数据、两个心跳的原始时间及年龄；监督器的 `lastAttempt` 保留这份快照。异常退出使用同一捕获入口，回退自身异常不会覆盖第一份快照。缺失、无效或超限诊断文件只标记 unavailable，不阻止原回退。

没有延长六秒 CT/预算租约或八秒心跳阈值，没有扩大 32 槽、准入、RT/BE 范围、完整 mark/NAT 语义、精确 CREATE/REMOVE 回执或重试次数。用户态 deadline 无法保证在内核不可中断等待或整个系统停顿时按时返回；发生这种情况仍诚实记录晚返、停止后续查询，并依赖既有 guardian 安全回退。

## 验证与部署

五/六 WAN 各 19 项回归（17 Lua、2 C）、61 Lua/12 shell 解析通过。新增实际源码模型 350 项覆盖健康三 AP、连续 AP 超时、TERM/KILL 耗尽、调度晚返、不完整拓扑拒绝、真实心跳退出分支、损坏诊断不阻断回退，以及监督器跨 launch 保留快照。路由器上使用实际 Lua/nixio 环境运行同一 350 项模型与原预算/回收 168 项模型通过；没有现场故障、拥塞或游戏流量注入。Lua 文件由目标解释器编译检查；没有 C/模块改动，因此没有更换或重建现网内核、固件和无线驱动。

部署前保存三个原文件和运行副本、两个事件的私有状态以及保护基线。独立 180 秒守护在控制连接断开时仍能调用原 NSS stop/完整恢复检查、还原三个原文件并通过原 singleton start；未知固件状态或未知文件版本不会强行覆盖。实际守护与回退代码的虚拟 I/O 模型 22 项通过。部署验证期间曾发现目标无 luac、监督器没有 RAM 副本以及 JSON 对象键顺序不稳定；都在现网切换前拒绝并修正检查，没有作为已通过记录。

一次正常 NSS stop 确认软件与固件状态恢复后，仅替换 collector、transaction、supervisor 三份持久 Lua；正常 start 自动重建 RAM 副本。完成后确认 sourceFresh、实际硬件准入、完整新预算及序号进展，再提交检查点，独立守护正常退出。原磁盘模块、启动 boot、六账号地址、认证、无线/代理/Tailscale、普通五 WAN 桶、PBR/NAT 规则和软件 CAKE 根/固定选项保持；既有 autorate 继续调整 bandwidth。NSS 与它拥有的 core guard 按正常生命周期切换，不能称为零加速间断；现存 NAT 未热迁移。
