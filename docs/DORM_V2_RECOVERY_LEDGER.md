# 恢复历史满表修复（已部署，满表故障为模型证据）

基线为 `codex/dorm-qos-v2` 的 `5cec1b057e97dcbfe678f495193f5848947d4676`。
开发时现网为 `224ee079a99bb43c6763bb54151a1c6aba7ab391`；后续获明确授权，
已在 2026-10-10 19:22:47 北京时间安装 `2996d405c9a96ec4d891887358f02f28de4e340c`。
[部署证据与尚未验收项](DORM_V2_RECOVERY_DEPLOYMENT.md)。

原 `blocked(e)` 在 32 条恢复历史仍有效时同时阻止所有没有历史的新流，
包括已经合格的 RT。历史条数现在仅限制恢复记账；健康新身份仍可等待一条
精确退休的槽位，然后正常首次准入。未确认退出的槽位仍不可复用。

仅删除全局拒绝条件会使没有历史空位的失败流无限重复首次准入。因此，
这种失败会精确撤销一次，等待原有终态 3/4/6，再在现有 `owned` 表中保留
软件退路标记。相同持续核验的 key、binding、class 不再添加或续租；
身份离开、明确撤销或 binding/class 变化之后才释放已确认退休的标记。
不会删除其他连接的恢复次数。该标记也不能成为另一个 RT 的抢占目标。

代价是每个仍存在的满表失败身份暂时占用一个管理槽位。如果所有槽位都
这样保留，后续流继续软件转发；这是一项显式、保守的容量退路。
恢复表与拥有表各自最多 32 项，事件最多 32 项，不新增无界失败集合。
原有身份 epoch 内最多两次恢复、1/3 秒等待、`!selected`、精确回执和
6 秒分类租约不变。缺失、pending 或错误代的 CREATE/FLUSH 观察不能证明失败。
未知的无通知固件规则消失仍没有可靠判据，未通过猜测字节增长来处理。

状态新增 `ledgerFull`、`quarantinedSlots`、`overflowFallbacks`；保留的
`newIdentityAdmissionPaused` 现为 false，仅表示恢复历史不会全局暂停新身份。
终态计数每次退休只计一次。

离线运行：

```sh
python3 tools/run_controller_offline.py --output /tmp/controller-offline.json
```

依赖 Lua 5.1、lua-cjson、Python 3 和 C 编译器。实际 writer 与测试使用拒绝
未模拟 I/O 的兼容层，9 个 Lua 套件和 2 个实际 C 源码套件通过；writer
740 个断言包含满历史健康 RT、迟到退休、满表失败隔离、120 秒持续身份、
120 秒耗尽重试及错序终态、来源失鲜、身份 epoch 变化。原 writer 在同一
测试中因满恢复表全局暂停新身份而失败。29 个维护 Lua 源码通过语法解析。
详细结果见 [证据](../evidence/dorm-v2-recovery-ledger.json)。

或 Wi-Fi 验收。未连接路由器执行测试，未安装候选或改变现网。
