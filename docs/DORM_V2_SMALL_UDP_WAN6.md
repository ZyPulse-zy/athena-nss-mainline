# 通用小 UDP 首包优先 WAN6 已启用

用户进一步明确希望按类似游戏的小 UDP 特征覆盖未知游戏。当前已在原官方中继规则后加入通用候选，目的地址无需位于 Steam 名单。仅处理新的 IPv4 br-lan UDP 原方向第一包、zone 0、无既有 WAN/proxy affinity；IP 总长 28–256 字节，通用分支另要求 UDP 总长 20–236 字节（至少12字节负载），源/目的端口 1024–65535。完整非 WAN fwmark 位保留，原 WAN/NAT 会话不迁移，TCP 和 IPv6 不纳入这个通用分支。

## 误识别边界与排除

**首包小不能证明后续低速，也不能证明进程是游戏。** 未知语音、UDP 控制、自定义隧道或先小后大的下载仍可能命中；后续变 BULK 时，该 NAT 会话继续在 WAN6，不能热迁回五路。现有 NSS source 按实际双向速率、pps、平均包长、持续样本及原预算作 RT/BULK/BE 判定，路由命中不强制 RT 或硬件准入。每账号原预算/十二队列、32槽、六秒租约、精确 CT/mark/NAT 和 firmware CREATE/REMOVE 回执合同保持。

保留原 DNS、QUIC/UDP443、已知 VPN/代理 mark 和端点、Tailscale、Fake-IP、私有/保留地址以及中大关键业务地址的保守排除。通用分支额外排除双方 STUN/TURN 常用端口3478/3479/5349、BT常用6881–6999；按负载字段排除STUN magic cookie、WireGuard类型1–4、QUIC长头候选与uTP v1头候选。这是有意保守的特征排除，可能漏掉具有相同字节开头的游戏，不能宣称已识别所有VPN/P2P或覆盖所有校内公网业务。非名单校内公网 UDP 若恰好像候选，仍存在残余风险。

通用分支每源 IPv4 新连接首包最多4次/秒、突发8，另有全局16次/秒、突发32；动态状态最多1024项、空闲30秒回收。超限和排除只回到原五路，不丢包。这些限制抑制新连接扇出，**不限制已命中连接的后续带宽**。官方中继分支保留原顺序/端口约束，不受这些额外启发式头部排除或通用限额影响。普通未命中流量继续 WAN1–5 的300桶和原双向 NSS RT 兜底。

## 维护和回退

延续现有健康循环、同boot六账号认证/健康、source/十二预算新鲜、双向标签和内核 gate 条件，两个分支资格均仅续15秒。失联、WAN6不可用或官方缓存七天过期时，两分支停止选新WAN6会话，旧会话保留归属；每日官方名单更新保留通用配置。没有新增常驻服务或调度。持久 owner 当前/待更新精确哈希约束扩展范围，已注册编辑由健康循环重建游戏专属对象，再续资格。

独立私有检查点保存本轮前的游戏两个源码、配置/owner和保护基线；回退只重建旧中继规则并恢复这些文件、重启健康进程，不停止NSS/source/认证、不改无线、共享路由表、普通五桶或NAT。部署前候选 nft check-only、部署后完整逆向 nft check-only均通过；首次失败时这个回退实际执行成功。后续其他任务若改动相关文件，应先核对 owner/哈希，不能盲用旧检查点覆盖新维护版本。

## 实测与模型

五/六 WAN 各14 Lua+2 C（16项）回归、55 Lua/12 shell语法通过。目标机运行实际策略124项及实际runtime虚拟I/O累计138项，覆盖未知地址/高端口、排除、限额资格、先小后大不迁移、残余误判、注册窄/宽范围编辑、重启/表丢失重建、每日更新、到期和独占清理。模型的语义标签是人工构造的反例，不是实网误识别率；目标没有进行造流、拥塞或故障注入。

首次目标检查发现 nft 对集合查询前后的 UDP 传输上下文要求，候选未启用，调整表达顺序后通过。第一次受控切换未登记pending配置哈希，健康循环拒绝新配置；通用资格未续期，已真实回退并保留失败证据。修正登记流程和定向模型后，在新检查点完成最终切换。只重启健康进程，NSS/source/认证/autorate/代理/Tailscale/无线服务核验PID、保护文件及原300五路桶保持。

最终45.37秒/15被动样本全部sourceFresh/native-running、两分支资格有效，pending/未确认0，来源暂停/恢复0/0。提交启用时通用规则计数为1个首包/166字节；不能据此证明游戏身份或该流后续带宽。本窗没有WAN6 UDP desired/NSS CREATE或同代硬件字节归属，故未宣称通用游戏双向NSS实际覆盖或延迟收益通过。六账号在线、WAN6双向RT标签7e66/7a66核验保持；实际冷启动/长期/真人游戏未测。
